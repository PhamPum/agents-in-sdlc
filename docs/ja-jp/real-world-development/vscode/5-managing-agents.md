GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。この作業はマシン上でリアルタイムに進むため、VS Code の Copilot Chat ではツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を採用または取り消したり、追加のプロンプトで会話を調整したりできます。エディターを離れる必要はありません。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムに監視する
- 提案されたファイル編集をレビューして採用する
- セッション中にエージェントへライト モードの切り替えも追加するよう依頼する

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。デフォルトのテーマが暗すぎると感じるユーザーのために、ライト モードも切り替えられるようにします。新しい会話を始めるのではなく、実行中のセッションに追加の作業を依頼します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにインラインで表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み取りや編集、実行を依頼するターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインに表示されます。
    - **Keep** を選択すると変更を採用します。
    - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などに許可が必要な場合、エージェントは一時停止し、**Allow** の確認を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に変更内容の概要が表示されます。

## エージェントにライト モードを依頼する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。会話を続けることで、エージェントはこれまでの作業、変更したコンポーネント、スタイルの方針、local storage の使い方を引き継ぎます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の作業から続けて変更を調べ、ライト モードの追加を提案します。
3. 変更が反映されるたびに、前と同じように確認します。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方針が意図と異なる場合は、チャット入力欄の横にある **Stop** ボタンで停止し、説明を加えたプロンプトを送信します。

> [!TIP]
> 実行中のセッションに追加の指示を送ると、最初からやり直すより速く調整できます。たとえば、「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを統合する」「両方の切り替えにキーボード ショートカットも追加する」などと依頼できます。

## 変更内容をレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など、カスタム エージェントのアクセシビリティ パターンが反映されているかを確認します。
4. 問題がなければ **Source Control** パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

このレッスンでは、Copilot Chat の agent mode を使って、実行中のセッションを監視、調整しました。各ファイル編集を確認し、採用または取り消し、コンテキストを保ったまま追加のプロンプトで作業を拡張しました。

次の内容を学びました。

- エージェントの作業をリアルタイムに監視する
- 個々のファイル編集を採用または取り消す
- 追加プロンプトで実行中のセッションを調整する

[次のレッスン][next-lesson]では、アクセシビリティ機能をプルリクエストとして公開し、このラボでローカルのカスタム エージェントが作成した変更をレビューします。
